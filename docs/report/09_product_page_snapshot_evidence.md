# 官网产品页面快照证据台账

## 1. 用途与证据边界

官网产品页面用于核验样本公司的产品线名称、应用场景和公开页面中可见的能力描述，是年报语义分析的补充证据，而不是年报语料的一部分。第二部分的词嵌入分析仍只使用 15 家公司 2025 年年报中切分出的指定章节；不得将官网文本或截图的 OCR 文字混入该语料后再将结果称为“年报语义结果”。

每一张截图或每一段文字快照都保留来源文件、原始/本地路径、哈希和页面序号。产品、功能、客户案例或数值等事实性表述应先回到相应页面人工复核；在尚未建立“产品线--截图页码”逐条映射前，不能因为某家公司拥有官网快照而将该公司全部产品线改标为已核验。

## 3. 与知识图谱的衔接

已运行 `src/verify_product_line_claims.py`，将第一阶段提出的 15 条“公司--产品线”主张与本研究限定的年报章节语料、11 家公司的 DOCX 文字快照逐条比对。结果写入 `outputs/tables/ai_product_line_verification.csv`：2 条为“全部锚点命中”，3 条为“部分锚点命中”，10 条为“当前语料与文字快照未命中”。其中，完整命中为东方财富的“妙想金融大模型、妙想投研助理”和宇信科技的“星睿智调、ChatBI”；部分命中为恒生电子的 WarrenQ、金证股份的 K-GPT 和新致软件的新知大模型。

“未命中”只表示在本次可复现的限定文本中证据不足，不等同于产品不存在。4 家仅有 JPEG 截图的公司已经完成文件归档，但尚未把截图逐页人工映射到具体产品线，故不会将其图谱关系升级为已验证。知识图谱中的“公司--产品线”及“产品线--技术方向”边均同步保留 `fully_verified`、`partially_verified` 或 `no_match_in_current_corpus` 状态，避免把初步选品主张误作事实结论。

后续人工复核应遵循以下流程：

1. 在公司对应快照中定位产品名称或解决方案标题，并记录 DOCX 段落或 JPEG 截图页序。
2. 将定位结果写入产品线证据表，填入产品线名称、产品类别、应用场景、证据文件、页序和人工复核日期。
3. 仅对有明确页面证据的图谱关系更新核验状态；模糊、营销性或无法辨认的表述继续保留为证据不足。

该流程使官网页面成为可追溯的产品事实来源，同时避免将页面列表、截图数量或词嵌入相似度误读为产品成熟度、收入贡献或技术性能。

## 4. 导入命令

```bash
python3 src/import_product_snapshots.py --inputs \
  '/path/to/1-4 产品文字版.docx' \
  '/path/to/5-8产品全部.docx' \
  '/path/to/13-15产品.docx'

python3 src/import_product_screenshots.py \
  --input-dir '/path/to/9-12'
```

导入脚本仅归档用户提供的原件和生成证据台账，不调用大模型、不改写页面内容，也不自动生成产品事实结论。
