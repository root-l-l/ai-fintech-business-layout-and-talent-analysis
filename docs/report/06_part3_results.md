# 6 第三部分实验结果

## 6.1 实验完整性

正式质量比较使用完整岗位文本：每条输入均包含招聘表中的职位名称、薪资范围、工作地点和职位描述正文，不包含人工金标准。模型为 `deepseek-v4-flash`，固定 `temperature=0`、JSON 输出模式、最大输出长度 1,200 token 和三并发调用。`FULL_R1` 覆盖 43 条岗位、15 家公司、3 个 Prompt，共 129 次调用；`FULL_R2` 对每家公司随机固定 1 条岗位复跑，共 45 次调用。共 174 个正式输出均通过 JSON 结构校验，且不存在重复的岗位-Prompt-轮次组合或缺失解析文件。

早期 `R1/R2` 运行仅将描述正文发送给模型，未向模型提供单列保存的职位名称、薪资和地点，因此不能用于这三项字段的公平评价。本节仅报告完整岗位文本的 `FULL_R1/FULL_R2` 结果。

## 6.2 评价口径

字段准确率采用预先固定的严格比较：职位名称、薪资、地点、学历和经验经规范化后完全一致；硬技能、软技能、AI 技术栈按无序集合完全一致；空白、`无`、`无明确要求`、`null` 等均按“原文未提及”处理。版本级字段提取准确率为八个字段准确率的宏平均。幻觉率定义为金标准为空但模型输出非空的字段比例；运行时间为记录的开始与结束时间差的均值。稳定性为同模型、同 Prompt、同一岗位在 `FULL_R1` 与 `FULL_R2` 之间的字段两两一致率，样本为 15 条分层岗位子样本。

这一严格规则对技能字段尤其苛刻：人工招聘表的技能栏常为长句或复合短语，而模型倾向将其拆分为原子技能。例如“熟练使用 Java、Spring、MyBatis”与 `[Java, Spring, MyBatis]` 具有相同信息，但不属于集合完全一致。因此技能字段的低严格分数应解释为“抽取粒度与源表标签粒度不一致”，不能单独推断为模型未识别任何技能。正式报告应同时展示字段级结果和一至两个原始输出例子。

## 6.3 结果解读

`P3` 的严格宏平均字段准确率最高（0.6744），并在职位名称、薪资范围和工作地点上达到 1.0000；其学历、经验字段准确率也高于 P1/P2。`P2` 的宏平均跨轮一致性最高（0.9583），反映出 Schema、字段定义和逐字段证据约束对稳定输出更有帮助。`P3` 的宏稳定性为 0.9333，AI 技术栈字段一致性为 0.6667，说明 one-shot 示例和更强的审计约束并不必然提高所有细粒度字段的重复一致性。

三版的宏幻觉率分别为 P1 0.0465、P2 0.0494、P3 0.0494，差异主要来自软技能字段：人工金标准未列出的软技能会被模型从文本中拆分出来。该指标只捕捉“金标准为空、模型非空”的情形，不能识别“金标准非空但内容错误”，故应报告为操作性幻觉率，而非全部事实性错误率。

在本次并发环境中，P1/P2/P3 的单请求平均端到端耗时分别为 3.119、4.846、2.986 秒。该时间包含服务端排队和网络波动，不能外推为不同模型或不同日期的绝对性能排序。实践上，若追求总体准确率可选择 P3；若优先批处理的重复一致性，可选择 P2，并在后续版本加入 AI 技术栈受控术语表或逐项证据校验。
