# 5 基于提示工程的职位需求结构化分析

## 5.1 实验目的与样本

本节比较三套 Prompt 对职位文本八个字段的结构化提取效果：职位名称、薪资范围、工作地点、硬技能、软技能、学历、经验和 AI 技术栈。实验从清洗后的 242 条职位记录中，按公司代码分层随机抽取；默认每家公司最多 3 条。随机种子、抽样规则和岗位 ID 均由 `src/prepare_prompt_experiment.py` 固化，确保不同 Prompt 在完全相同的职位样本上比较。模型输入使用完整岗位文本：源工作簿中分列保存的职位名称、薪资范围和工作地点，与职位描述正文拼接后共同输入。这些均为观察到的招聘字段，非人工金标准泄露。

## 5.2 三套 Prompt 的差异

P1 为固定 JSON 输出结构下的 zero-shot 直接抽取基线；P2 增加字段定义、缺失值处理和逐字段原文证据约束；P3 在 P2 的基础上加入一个与研究样本无关的虚构 one-shot 示例、反幻觉规则和静默自检，要求没有原文证据即置空，并禁止把“优先/加分项”改写成必备条件。三版 Prompt 位于 `docs/prompts/prompt_v1.md` 至 `prompt_v3.md`。三版共享相同八个被评价字段，故指标差异可归因于 Prompt 约束的逐级增强，而非输出字段改变。

## 5.3 指标与诚信约束

字段准确率定义为模型输出经规范化后与人工金标准完全一致的比例；幻觉率定义为人工金标准为空、但模型输出非空的比例；运行时间取每条调用的结束时间减开始时间。对列表字段，正式实验应以规范化的集合比较或人工复核为准。稳定性通过相同职位、相同 Prompt、相同模型的多次独立调用来评估，并报告字段一致率。

本研究的人工金标准采用研究团队提供并确认的结构化招聘表：其中的岗位、薪资、地点、技能、学历、经验与 AI 技术栈字段均保留原始表述；空白、`无` 和 `无明确要求` 统一表示“原文未提及”，而非待补充。金标准由 `src/build_gold_annotation_draft.py` 与 `src/finalize_gold_annotations.py` 生成，并保留工作簿、工作表和行号来源。薪资均以人民币解释，除明确标注日薪、面议、未公示或未提及外，`K` 表示千元人民币月薪；`·14薪`、`·15薪` 等仅表示年发薪月数，不能直接替代月薪。

实际模型调用输出的质量比较必须固定为同一模型、同一调用轮次；不同模型的试运行记录仅作审计保留，不能与正式实验结果合并。早期仅输入职位描述正文的 `R1/R2` 未向模型提供职位名称、薪资和地点，故不具备这三项字段的公平可评性，不报告其指标。正式实验采用完整岗位文本并使用独立运行标识 `FULL_R1/FULL_R2`。模型原始输出与时间戳写入 `data/reference/llm_outputs.csv` 后，运行 `src/validate_llm_outputs.py --model-id <实际模型ID> --run-ids FULL_R1 FULL_R2`、`src/evaluate_llm.py --model-id <实际模型ID> --run-id FULL_R1` 和 `src/evaluate_prompt_stability.py --model-id <实际模型ID> --run-ids FULL_R1 FULL_R2`。

## 5.4 可复现执行步骤

运行 `src/build_prompt_run_inputs.py` 后，P1、P2、P3 各产生 43 条 JSONL 输入。第一轮以全部 43 条岗位比较字段抽取质量，共 129 次 API 调用。为降低重复调用成本，第二轮稳定性检验采用按公司分层、每家公司随机固定 1 条岗位的 15 条子样本，共 45 次调用；随机种子由 `src/prepare_stability_sample.py` 固化。调用层固定 `temperature=0`、JSON 输出模式与 1,200 个最大生成 token；在兼容服务中可关闭思考模式以控制延迟。每次真实模型调用保留 `job_id`、`prompt_version`、`run_id`、`model_id`、开始与结束时间、原始输出，以及解析后的 JSON 路径；在 `src/validate_llm_outputs.py` 通过结构校验后运行 `src/evaluate_llm.py`。`src/evaluate_prompt_stability.py` 计算逐字段两两一致率。列表字段按无序集合比对，避免因技能列举顺序不同而误判。稳定性结果仅外推至该 15 条分层子样本。
